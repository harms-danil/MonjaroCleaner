# MCleaner — дизайн

Дата: 2026-11-22. Статус: черновик на согласование.

## Зачем

Магнитола Geely Monjaro (ECARX, Android 11, Qualcomm SA8155) с установленным GMS 1.3 иногда подтормаживает, особенно при запуске и открытии приложений. Вероятная причина — нехватка ОЗУ: Google-сервисы и сторонние приложения висят в фоне. Нужно APK-приложение, которое:

1. показывает, сколько ОЗУ, накопителя и CPU занято и **кто** это занимает;
2. одним нажатием освобождает память и чистит кэш, не ломая то, что нужно в дороге.

Успех: после «Ускорить» свободной ОЗУ заметно больше, а приложения открываются быстрее. При этом навигация, музыка и функции машины продолжают работать.

## Цели / не-цели / анти-цели

**Цели**
- Обзор: ОЗУ (всего/занято/свободно), накопитель (всего/занято, суммарный кэш), загрузка CPU и температура SoC (если удаётся прочитать).
- Список приложений с ОЗУ (PSS) и размером кэша, сортировка и фильтр «только работающие».
- «Ускорить»: force-stop фоновых пользовательских приложений вне белого списка и очистка кэша всех приложений.
- Поштучно: «Остановить», «Очистить кэш», «Заморозить» (только пользовательские приложения), «Разморозить».
- Очистка мусора на накопителе: скан → список с объёмом → удаление после подтверждения.
- Белый список, автоускорение после старта магнитолы, инструкция и статус Shizuku.
- Два режима: **полный** (Shizuku, права ADB shell) и **базовый** (без Shizuku). Без Shizuku приложение работает, но умеет меньше.

**Не-цели (v1)**
- Root-режим.
- Постоянный фоновый «убийца задач» по таймеру.
- Виджет рабочего стола, вывод на приборную панель.
- Сеть, аналитика, реклама. Приложение не ходит в интернет совсем (нет `INTERNET`).

**Анти-цели (провал, даже если «работает»)**
- Остановилась навигация или музыка во время движения.
- Тронуты системные пакеты машины (`com.ecarx.*`, `com.geely.*`, любые с `FLAG_SYSTEM`) — их никогда не останавливаем и не замораживаем.
- Лагов стало больше из-за цикла «убили → система перезапустила».
- Удалены пользовательские файлы без явного подтверждения.

## Ограничения

- Android 11 (API 30), но `minSdk = 28` на случай других прошивок. Горизонтальный экран примерно 1920×720 или шире, управление пальцем.
- Root нет. ADB и режим разработчика включаются. Shizuku ставится отдельно (APK с GitHub) и запускается через ADB/беспроводную отладку. **После перезагрузки магнитолы Shizuku без root, как правило, нужно запускать заново**, поэтому автоускорение срабатывает, только если Shizuku уже работает.
- Сборка на этом Mac: JDK из Homebrew, Android SDK в `~/Library/Android/sdk` (platform 37, build-tools 36), Gradle 9.5 есть в кэше. Тулчейн как в соседнем `DiPlay`: AGP 9.3.0, Kotlin 2.2.10, Compose BOM 2026.02.01.
- Установка: `adb install` или через флешку файловым менеджером.

## Подходы (рассмотрены)

1. **Без особых прав.** Только публичные API. Нельзя чистить чужой кэш (`CLEAR_APP_CACHE` системное), нельзя узнать ОЗУ чужих процессов и CPU (`/proc` закрыт с Android 8), `killBackgroundProcesses` почти бесполезен. Слабый эффект.
2. **Shizuku + фолбэк на базовый режим — ВЫБРАН.** Команды выполняются от uid `shell` (2000): `am force-stop`, `pm trim-caches`, `dumpsys meminfo`, `pm disable-user`, чтение `/proc/stat`. Эффект близок к root, но root не нужен. Цена: разовая настройка Shizuku.
3. **Root.** Отброшен: на Monjaro root почти ни у кого нет, риск повредить прошивку.

## Как устроено

### Стек
Kotlin, Jetpack Compose Material 3, один модуль `app`. Название «MCleaner» (выбор пользователя), пакет `app.mcleaner` *(пакет — моё решение)*. Shizuku: `dev.rikka.shizuku:api` и `provider` 13.1.5. Простая архитектура: `ui` (экраны + ViewModel) → `domain` (сценарии) → `data` (источники). DI вручную, без Hilt.

### Слой привилегий
Интерфейс `Privileged`, у него две реализации:
- `ShizukuPrivileged` — Shizuku **UserService** (отдельный процесс от shell), внутри `Runtime.exec` команд. Результат: stdout, код возврата.
- `NoPrivileged` — заглушка: каждая операция возвращает «недоступно», UI показывает фолбэк.

Состояние Shizuku: `не установлен` / `не запущен` / `нет разрешения` / `готов`. Отслеживаем через `Shizuku.addBinderReceivedListener` и `addBinderDeadListener`.

### Источники данных
| Что | Полный режим | Базовый режим |
|---|---|---|
| ОЗУ всего/свободно | `ActivityManager.getMemoryInfo` (+ `/proc/meminfo` для «доступно») | то же |
| ОЗУ по приложениям | парсинг `dumpsys meminfo` (секция «Total PSS by process») | недоступно |
| Работающие приложения | из того же `dumpsys meminfo` | недоступно |
| Накопитель | `StatFs` на `/data` | то же |
| Кэш по приложениям | `StorageStatsManager.queryStatsForPackage` (доступ к статистике выдаём сами через `appops set … GET_USAGE_STATS allow`) | то же, но пользователь выдаёт доступ в настройках |
| CPU | дельта `/proc/stat` за 1 с через shell | «—» |
| Температура | `/sys/class/thermal/thermal_zone*/temp`, best-effort, иначе скрыть | то же |
| Список пакетов | `PackageManager.getInstalledApplications` (`QUERY_ALL_PACKAGES`) | то же |

Обновление: обзор каждые 2 с, пока экран виден. Список приложений обновляется при открытии экрана и по pull-to-refresh/кнопке.

### Действия
| Действие | Полный режим | Базовый режим |
|---|---|---|
| Остановить приложение | `am force-stop <pkg>` | открыть системную карточку приложения |
| Очистить кэш одного | `IPackageManager.deleteApplicationCacheFilesAsUser` через `ShizukuBinderWrapper` (у shell есть `DELETE_CACHE_FILES`). Если не сработает — поштучная кнопка ведёт в карточку приложения | карточка приложения |
| Очистить весь кэш | цикл поштучной очистки по всем пакетам, **кроме** белого списка и `com.ecarx.*` / `com.geely.*` (офлайн-карты и треки не трогаем). Если поштучная не работает — фолбэк `pm trim-caches 999G` с предупреждением «очистится кэш и навигатора тоже» | недоступно, баннер |
| Заморозить / разморозить | `pm disable-user --user <U> <pkg>` / `pm enable --user <U> <pkg>`, где `U` = `am get-current-user` (магнитола может быть многопользовательской). Только для не-системных. Ведём список замороженных, чтобы их можно было вернуть | недоступно |
| Мусор на накопителе | скан и удаление через shell (виден и `Android/data`) | скан общего хранилища, нужен `MANAGE_EXTERNAL_STORAGE` (выдаём через appops в полном режиме или просим в настройках) |

**«Ускорить»** — что делает по шагам:
1. Снимок свободной ОЗУ «до».
2. Кандидаты: работающие, не системные, не в белом списке, не текущий лаунчер, не текущая клавиатура, не само приложение, не Shizuku, не приложение на переднем плане, **не приложение с foreground-сервисом или активной медиасессией** (`dumpsys activity services`, `dumpsys media_session`). Иначе можно остановить радио или подкаст, которого нет в белом списке.
3. `force-stop` каждого кандидата.
4. «Очистить весь кэш» (по правилам таблицы выше).
5. Через 2 с снимок «после», показываем «Освобождено X МБ ОЗУ, Y МБ кэша».

В базовом режиме список работающих приложений недоступен, поэтому «Ускорить» делает `killBackgroundProcesses` вслепую по всем не-системным пакетам вне белого списка. Это безопасно: так завершаются только кэшированные фоновые процессы. Результат честный: «для полного эффекта нужен Shizuku».

Все команды с пользователем берут `U` из `am get-current-user`, а не жёсткий `0`. *(Замечания ревьюера, решены мной.)*

### Белый список
Хранится в DataStore. По умолчанию в нём: Яндекс Навигатор, Яндекс Карты, Google Maps, 2ГИС, Яндекс Музыка, Spotify, VK Музыка, Shizuku, DiPlay *(точные имена пакетов уточнит разработчик)*. Системные пакеты в белый список не нужны: их не трогаем по правилу. Пользователь добавляет и убирает приложения переключателем в списке.

### Автоускорение
Магнитола иногда загружается полностью, а иногда просыпается из сна (ответ пользователя), поэтому поддерживаем оба триггера:
- **Загрузка**: ресивер `BOOT_COMPLETED` → через 90 с одноразовая задача WorkManager.
- **Пробуждение**: `SCREEN_ON` / `USER_PRESENT` нельзя слушать из манифеста. Поэтому, пока автоускорение включено, работает лёгкий foreground-сервис с тихим постоянным уведомлением, а в нём динамический ресивер. Сервис стартует при загрузке и при открытии приложения. После пробуждения ждём 30 с.

Общая логика: если Shizuku готов — «Ускорить» тихо, без UI, с уведомлением о результате. Если не готов — ничего не делаем. Между запусками не меньше 10 минут, чтобы не провоцировать цикл «убили → перезапустилось». По умолчанию выключено.

### Google-сервисы
Настройка «Останавливать Google-сервисы при ускорении», по умолчанию **выключена** (решение пользователя). Пакеты: `com.google.android.gms`, `com.google.android.gsf`, `com.android.vending`. Выключена: им только чистится кэш, они не останавливаются и не замораживаются. Включена: они попадают в кандидаты «Ускорить» (force-stop), даже если помечены как системные. Это единственное исключение из правила «системные не трогаем». Замораживать их нельзя никогда.

### Интерфейс
Утверждён макет (2 экрана). Левая вертикальная навигация: Обзор, Приложения, Очистка, Настройки.
- **Обзор**: три карточки (ОЗУ / накопитель / CPU), топ-3 по памяти, большая кнопка «Ускорить» с описанием, что она сделает. Чип статуса Shizuku справа сверху.
- **Приложения**: чипы сортировки (по памяти / по кэшу / только работающие), строки с иконкой, именем, бейджами («системное», «в белом списке», «заморожено»), ОЗУ, кэшем и кнопкой действия. Тап по строке открывает панель со всеми действиями и переключателем белого списка.
- **Очистка**: кнопки «Очистить кэш всех приложений» и «Найти мусор», после скана — группы (APK, логи, временные, кэш миниатюр, пустые папки) с объёмом и чекбоксами, затем «Удалить выбранное» с подтверждением.
- **Настройки**: статус и пошаговая инструкция Shizuku, белый список, автоускорение, «Останавливать Google-сервисы», «Разморозить всё», версия.
- Только тёмная тема, крупные элементы (касание от 56 dp, основной текст от 18 sp), только горизонтальная ориентация.
- Без Shizuku сверху висит баннер «Включите полный режим» со ссылкой на инструкцию.
- Язык — русский.

### Ошибки
Неудачная shell-команда не роняет приложение: в результате показываем, что не сработало (например, «2 приложения не остановлены»). Нет нужного разрешения → кнопка ведёт на экран, где его выдают. Shizuku умер посреди операции → переходим в базовый режим, показываем тост.

### Тесты
- Unit-тесты (JVM): парсеры `dumpsys meminfo`, `/proc/stat`, `/proc/meminfo`, отбор кандидатов для «Ускорить» (белый список, системные, передний план), классификатор мусора. Фикстуры — реальные выводы команд, в том числе образцы с Android 11.
- Проверка на машине — за пользователем: чек-лист в README (базовый режим, полный режим, «Ускорить» во время навигации — навигатор живой).

### Результат сборки
Подписанный APK (локальный keystore генерируется один раз и лежит вне git) → `monjaro_dev/MCleaner-<версия>.apk`. README: установка, настройка Shizuku на магнитоле, чек-лист проверки.
